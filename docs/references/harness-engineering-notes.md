# Harness Engineering Notes

The repo uses a lightweight agent operating harness so work can be resumed across sessions.

## Conventions

- `AGENTS.md` is the short entry point.
- `docs/agent/` contains operating rules.
- `docs/architecture/` records durable architecture context and boundaries.
- `docs/product/` records product truth and user journeys.
- `docs/exec-plans/active/` contains in-progress implementation plans.
- `docs/exec-plans/completed/` contains finished plans.
- `scripts/validate-harness.sh` checks required harness files and stale placeholders.
